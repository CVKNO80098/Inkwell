# 为什么要安装 Inkwell 的自签名证书

## 一句话

`Inkwell.exe` 使用了一张**自签名代码签名证书**。Windows 默认只信任公共 CA 的根证书，所以第一次看到这个 exe 时会显示「发布者未知」或「签名无效」。把随包的 `Inkwell-selfsigned.cer` 安装为受信任的根证书与发布者后，Windows 才能确认：这个 exe 确实由 Inkwell 的构建者签名，且签名后没有被修改过。

## 这个文件的签名信息

| 项目 | 值 |
|---|---|
| 签名者 | `CN=Inkwell Self-Signed, O=Inkwell` |
| 证书指纹（SHA-1） | `CD2CA40681CF884B8398D596BF07CAD89CB8D731` |
| 证书有效期 | 2026-11-20 至 2031-11-21 |
| 密钥 | RSA 3072 / SHA-256 |
| `Inkwell.exe` SHA-256 | `72045D0C160B49729E90772F91BDCBA91E12EE9C80D1C31106C163D9A3797DBA` |
| `Inkwell-selfsigned.cer` SHA-256 | `CE0DEAD4B3CAA73FAA58B18942EA71FEF7C18C799F9165225B5FD37A792444FF` |

证书只包含**公钥**。签名用的私钥只存在于签名进程的内存中，签名完成后即销毁，没有写入磁盘，也没有随包分发。

## 为什么 Windows 会提示「未知发布者」

Windows 验证 exe 签名时，会沿着证书链一直找到它信任的根证书。自签名证书的“根”就是它自己，而这张根证书不在系统的受信任列表里，因此链验证失败。安装证书的动作，就是告诉 Windows：

> 我确认这张公钥属于 Inkwell 的构建者，愿意信任由它签发的签名。

需要特别说明：**SmartScreen 并不只检查“从网上下载”的文件。** 从资源管理器双击一个没有信誉的 exe 时，无论它有没有 `Zone.Identifier`、无论签名是否可信，SmartScreen 都可能拦截。用 `cmd /c start` 之类的方式直接启动进程则不会经过资源管理器的这条检查——这就是自动化测试里不弹窗、而你双击却会弹窗的原因。

## 安装后能得到什么

- `Get-AuthenticodeSignature` 的状态从 `UnknownError` 变为 `Valid`
- exe 属性 →「数字签名」里能看到签名者和指纹
- 如果有人修改了 exe，签名校验会失败，Windows 会提示文件被篡改

## 安装后**不能**得到什么

- **不能保证 SmartScreen 一定放行。** 即使导入了证书，SmartScreen 仍会按文件下载量和信誉判断；自签名没有公共 CA 背书，仍可能弹出「Windows 已保护你的电脑」，需要点「更多信息 → 仍要运行」。安装证书改变的是“签名链是否可信”，不是“这个文件有没有信誉”。
- **不能让别人也信任。** 其他电脑没有导入这张证书时，仍然显示未知发布者或签名无效。
- **不能证明“绝对没有病毒”。** 签名只证明“是谁签的、签名后有没有被改”，不是杀毒结论。安全说明见下一节。

## 如何验证文件没有被掉包

在解压后的目录打开 PowerShell：

```powershell
Get-FileHash .\Inkwell.exe -Algorithm SHA256
Get-FileHash .\Inkwell-selfsigned.cer -Algorithm SHA256
```

把输出与上表比对。再查看签名：

```powershell
Get-AuthenticodeSignature .\Inkwell.exe | Format-List Status, StatusMessage, SignerCertificate
```

导入证书前状态通常是 `UnknownError`（根不受信任）；导入后应为 `Valid`。也可以在 exe 上右键 →「属性」→「数字签名」→ 选中签名 →「详细信息」→「查看证书」，核对指纹。

## 安装步骤（只影响当前用户，不需要管理员）

1. 双击 `Inkwell-selfsigned.cer`
2. 点「安装证书」→「当前用户」→「下一步」
3. 选择「将所有的证书放入下列存储」→「浏览」→ 选「**受信任的根证书颁发机构**」→「确定」
4. 「下一步」→「完成」→ 安全警告选「是」
5. 再次双击同一个 `.cer`，这次在第 3 步选「**受信任的发布者**」，重复安装
6. 重新运行 `Inkwell.exe`

也可以用 PowerShell（会弹出安全警告，确认即可）：

```powershell
Import-Certificate -FilePath .\Inkwell-selfsigned.cer -CertStoreLocation Cert:\CurrentUser\Root
Import-Certificate -FilePath .\Inkwell-selfsigned.cer -CertStoreLocation Cert:\CurrentUser\TrustedPublisher
```

## 卸载证书

```powershell
Get-ChildItem Cert:\CurrentUser\Root, Cert:\CurrentUser\TrustedPublisher |
    Where-Object { $_.Subject -like '*Inkwell Self-Signed*' } | Remove-Item
```

或在「certmgr.msc」→「受信任的根证书颁发机构」/「受信任的发布者」里删除对应证书。

## 安全说明：关于「没有病毒」

我必须诚实：**任何软件都无法给出字面意义上的“绝对无病毒保证”**，包括商业软件。签名和哈希能证明来源与完整性，不能替代杀毒扫描。

我能提供的是可核验的实现事实：

1. **不联网。** 程序没有自动更新、遥测、上传功能，也没有 HTTP/Socket 客户端代码。
2. **不驻留。** 不安装服务、不写启动项、不建计划任务、不注册文件关联。
3. **不写系统目录。** 设置与备份只写在 exe 同级的 `data\` 目录（便携模式），或你自己选择的 `%APPDATA%\Inkwell`。
4. **不捆绑第三方组件。** 发行包只有一个 exe，不附带 DLL、安装器或运行库；仅依赖 Windows 自带的 .NET Framework 4.7.2。
5. **只在你主动操作时调用系统程序。** 点击文档里的链接会用默认浏览器打开；「在资源管理器中显示」会打开 Explorer。
6. **可复现构建。** 源码与 `build.ps1`（无 NuGet、直接调用系统 Roslyn 编译器）在项目仓库中，可自行编译比对哈希。
7. 上表的 SHA-256 可用于确认你拿到的文件与签名时完全一致。

建议你仍然：

- 用 Windows Defender 或火绒对 `Inkwell.exe` 做一次自定义扫描；
- 把文件上传到 [VirusTotal](https://www.virustotal.com/) 做多引擎复核；
- 如果哈希或证书指纹与上表不一致，**不要运行**，说明文件已被替换。

## 常见问题

**为什么不用公共 CA 证书？**
需要付费并完成实名核验，个人项目成本较高。自签名适合个人使用和小范围内测；公开分发仍建议购买 OV/EV 代码签名证书。

**为什么每版指纹可能不同？**
私钥不落盘，重新执行 `build\sign-selfsigned.ps1` 会生成一张新证书。新证书需要重新导入；请以每个发行包内的 `.cer` 和说明为准。

**安装根证书安全吗？**
这里只信任这一张公钥证书，且它的私钥已经销毁。你可以随时按上面的命令删除。不要安装来源不明的根证书。

**SmartScreen 还是拦截怎么办？**
点「更多信息 → 仍要运行」。这是微软按文件信誉做的拦截，不是病毒判定；安装证书不会自动获得信誉。要彻底消除，只能使用公共 CA 的代码签名证书并积累下载量。
